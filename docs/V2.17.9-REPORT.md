## 2. `verify.sh` — проверка, которая ловит расхождение, а не литерал

Добавлен блок `4.5 /config отдаёт ставку Tier 6`. Ключевое решение: тест **не ищет строку
`"0.0002"`**. Литерал прошёл бы и на захардкоженном ответе, разошедшемся с реальной
комиссией. Вместо этого тест:

1. читает `/config` с публичного URL;
2. `require`-ит `config.js` **того же коммита**;
3. сверяет `ORCHESTRATION_FEE_TAR`, `CASHBACK_TAR`, `cashbackRate` с допуском `1e-9` на `rate`.

Вердикт уходит в `ok()` / `no()`, то есть влияет на `FAIL` и **exit-код**.

### Доказательство, что тест не декоративный — три прогона

```
# A. текущий прод (до раскатки) — должен краснеть
$ curl -s $PROD/config | node … 
NO_TIER6|в ответе нет блока TIER6

# B. новый код локально — должен зеленеть
$ curl -s http://127.0.0.1:3099/config | node …
OK|fee=0.0002 cashback=0.0001 rate=0.5

# C. подделанный ответ (старая ставка 0.0005 и rate 0.2) — должен ловить расхождение
$ echo '{"TIER6":{"ORCHESTRATION_FEE_TAR":0.0005,"CASHBACK_TAR":0.0001,"cashbackRate":0.2}}' | node …
MISMATCH|fee 0.0005≠0.0002, rate
```

Три состояния — три разных вердикта. Тест проверяет поведение, а не наличие строки.

## 6. Находка, которой не было в задании: ставка B′ экономически не проверена

Директива просила «разделить: 13 вызовов, из них N по старой ставке, M по новой».
Разделение сделано **запросом к БД**, а не арифметикой.

```sql
SELECT feeGrossTar, COUNT(*) FROM tier6_calls GROUP BY feeGrossTar;
→ 0.0005 | 13          -- единственная группа

SELECT MAX(createdAt) FROM tier6_calls;
→ 2026-10-29T16:51:30.820Z
```

Построчно (13 строк, все одинаковые по сплиту):

```
id | feeGross | cashback | burn | treasury | fundedBy | provider | createdAt
…  | 0.0005   | 0.0001   | 0.0002 | 0.0002 | client | openrouter | 2026-10-28 … 2026-10-29
```

**Вывод: все 13 вызовов — по старой ставке `0.0005`. По B′ `0.0002` — ноль вызовов.**
Последний вызов 29.10, раскатка B′ — 01.11.

### Почему это важно сформулировать точно

- **Нельзя сказать «B′ работает»** — это подмена «раскатано» на «проверено работой».
- **Нельзя сказать «B′ сломана»** — отказов по ней не было, потому что не было вызовов.
- **Корректно:** «B′ раскатана, подтверждается через `/config`; экономически не проверена».
- **Как проверить после первого вызова:** первое `feeGrossTar = 0.0002` в `tier6_calls` —
  доказательство. Сплит при этом обязан быть `0.0001 + 0.00005 + 0.00005 = 0.0002`.

Это ровно тот класс дефекта, с которым борется Code-First Rule: цифра в отчёте могла
выглядеть как «экономика B′ живёт», хотя за ней стояли вызовы предыдущей ставки.

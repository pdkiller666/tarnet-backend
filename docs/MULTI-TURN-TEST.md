# MULTI-TURN-TEST — помнит ли модель предыдущий ход

Документ отвечает на один вопрос: **как доказать, что живая модель помнит разговор, а не только получает историю**. Это разные утверждения, и до `2.29.7` в проекте было доказано только первое.

## Что уже доказано и что нет

| Утверждение | Чем доказано | Статус |
|---|---|---|
| История `messages[]` доезжает до воркера и совпадает по хешу | `test-conversation.js`, 30 проверок | ✅ доказано |
| Сервер отказывает при расхождении `prompt` и последнего хода | `400 PROMPT_MESSAGES_MISMATCH`, есть в гейте | ✅ доказано |
| Модель, прочитав историю, **отвечает** так, будто помнит | `scripts/check-multi-turn.js` | ⏳ ждёт живого воркера |

Разница принципиальная. Транспорт можно починить и проверить без модели: он зелёный и сейчас. Память — свойство модели, и без неё проверить его нечем.

**Почему это не проверяется шаблоном.** Без воркера сервер отвечает детерминированным ответом (`llm_mode: deterministic_fallback`, `fallback_reason: no_workers`). Шаблон имени не помнит по построению — он не читает историю вообще. Провал памяти на шаблоне был бы измерением шаблона, а не модели.

## Как проверить

Три вещи должны быть на месте:

1. **Воркер запущен на ПК владельца** — `active_workers >= 1` в `/health`.
2. **Ollama отвечает** — на самом ПК `ollama list` показывает модель.
3. **Сервер видит канал** — `/health` → `llm_mode` не `deterministic_fallback`.

Проверка запускается с любой машины, где есть Node:

```bash
node scripts/check-multi-turn.js
```

Против локального сервера:

```bash
node scripts/check-multi-turn.js --url http://localhost:3006
```

Машиночитаемый вывод (для автоматизации):

```bash
node scripts/check-multi-turn.js --json
```

## Что именно происходит

Три **отдельных** запроса к `/inference`, каждый со своей историей:

| Шаг | Что отправляется | Зачем |
|---|---|---|
| 1 | `Меня зовут Илья. Запомни это.` | имя попадает в историю |
| 2 | история + `Как меня зовут?` | проверка немедленного recall |
| 3 | история + `Назови моё имя одним словом.` | проверка, что память не однократна |

Третий запрос **не содержит имени**. Если модель его назовёт — она прочитала историю. Если нет — не прочитала, и это факт о воркере.

`prompt` в каждом запросе равен последнему ходу пользователя: сервер сверяет их и отказывает `400 PROMPT_MESSAGES_MISMATCH` при расхождении. Это не придирка — HITL-одобрение связывается хешем с содержимым, и подмена истории, оставшаяся со старым `prompt`, обошла бы это связывание.

## Коды возврата

| Код | Значение | Что делать |
|---|---|---|
| `0` | модель помнит имя | зелено, сеть работает end-to-end |
| `1` | модель НЕ помнит при живом воркере | настоящий провал: воркер не передаёт историю в модель |
| `2` | плохой аргумент | поправить вызов |
| `3` | живого воркера нет | **не провал** — запустить воркер и повторить |
| `4` | сеть или сервер недоступны | проверить адрес и сервер |

Код `3` отделён от `1` намеренно. Слить их значило бы объявить модель виноватой в том, что её не запустили, — та же ошибка, что месяц диагностики на неверном домене.

## Если код `1`: где искать

Транспорт доказан, значит дефект между расшифровкой задачи и вызовом модели. Порядок проверки:

1. **`worker-demo.js`** — передаются ли `messages` в Ollama. Если уходит только последний ход, память невозможна при исправном транспорте.
2. **`conversation.js`** — не обрезала ли `truncateMessages` имя. При бюджете 3072 токена короткий диалог не режется, но проверить надо: обрезка идёт по приоритетам `system → первый user → последний user → пары LIFO`.
3. **Ollama** — не запущена ли модель с `num_ctx`, урезанным до одного хода.

Начинать с первого: два остальных дают тот же симптом, но встречаются реже.

## Чего этот тест не делает

- **Не проверяет tool calls.** Сквозная цепочка «модель просит инструмент → сервер считает → модель отвечает по числу» — отдельная проверка, см. `MASTER-PLAN.md`, этап 9.
- **Не проверяет память между сессиями.** Речь о памяти внутри одного разговора; треды хранятся в браузере (`tarnet_memory_v1`) и на сервер не уходят.
- **Не проверяет качество ответов.** Только факт recall. Модель может помнить имя и отвечать плохо — это другой разговор.

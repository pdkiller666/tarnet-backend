## Слайд 2 — Проблема

**Инференс централизован и дорог.**

- Пользователь платит за токены, но не знает, что модель ответила честно.
- Владелец GPU простаивает: его мощность не продаётся, потому что нет способа доказать выполненную работу.
- Между ними — платформа, которая забирает маржу и хранит промпты.

**Ключевой дефект:** нет проверяемого доказательства выполненной работы. Без него рынок не собирается — никто не платит за вычисление, которое нельзя подтвердить.

**Заметки:** Это не «AI дорого». Это «нет примитива доверия между тем, у кого есть GPU, и тем, кому нужен ответ».

## Слайд 3 — Решение

**Протокол, который ведёт независимый реестр выполненной работы.**

Три элемента:

1. **dPoUW** — каждая единица работы даёт подписанный чек с объёмом (CWU) и наградой.
2. **Инвариант сохранения** — выплаты + сжигание + казна + роялти = оборот леджера, всегда, с точностью до 6 знаков.
3. **Единый токен `$TAR`** — одна единица во всех потоках: награда, комиссия, burn, казна, роялти.

**Проверяемость вместо доверия:** любой считает инвариант из `GET /summary` и `GET /health`. Расхождение видно всем.

**Заметки:** Не говорить «децентрализация». Говорить «проверяемый учёт». Это то, что уже работает.

## Слайд 4 — Как это работает

```
Пользователь (PWA)
      │  запрос
      ▼
   VPS-роутер ──► воркер (ПК владельца) ──► модель (Ollama)
      │                                        │
      │◄────────────── ответ ──────────────────┘
      │
      ▼  чек dPoUW: CWU → награда → burn / казна / роялти
   Леджер (SQLite) ──► инвариант: delta = 0
```

**Три режима инференса:** `worker` (живая модель) → `external_api` (внешний провайдер) → `deterministic_fallback`.
Приоритет — живой воркер. Заглушка включается, только когда исполнителей нет.

**Заметки:** Схема простая намеренно. Сложность — в леджере, и она там, где деньги.

**Заметки:** Честно сказать: ключ клиента не покидает его устройство дольше одного запроса, в БД не пишется.

**Осторожно с цифрой «18 моделей»:** это размер каталога, а не список протестированных. Живой вызов с ключом подтверждён для OpenRouter (сквозной, 72 токена), плюс отказы в правильном порядке для остальных. Together, Fireworks и Mistral идут по тому же OpenAI-совместимому коду, но без ключей в окружении их успешная ветка не исполнялась ни разу — говорить «работают» нельзя. Yandex и GigaChat отвечают `501 PROVIDER_NOT_IMPLEMENTED` до сети и до проверки ключа: в каталоге они есть, вызова нет. Это разделение — не оговорка, а суть: наличие строки в `/models` не равно поддержке.

**Отдельно про Gemini и Groq:** адаптеры и ключи для них в коде есть (`llm-adapter.js`, `PROVIDER_ENDPOINTS`), но в каталог `/models` они не внесены, поэтому в цифре «18» их нет. Не называть их числом каталога — иначе цифра разъедется с тем, что видит инвестор.

**Безопасность: привязка устройства — подпись, а не заявка (`2.12.8`).**

| Гейт | Ответ |
|---|---|
| Нет подписи или nonce | `400 SIGNATURE_REQUIRED` |
| Кривой nonce | `400 NONCE_INVALID` |
| Чужой ключ / мусорная подпись | `403 DEVICE_NOT_OWNED` |
| Повтор nonce | `409 NONCE_REUSED` |

Подписывается `<scope>:<owner>:<device>:<nonce>` ключом Ed25519; scope у привязки и отвязки разный, а подпись проверяется **до** поиска устройства в сети — иначе код ответа выдавал бы, какие адреса существуют. Старые балансы без ключей больше не заморожены: `POST /migrate/claim` переносит их на текущий кошелёк, подпись ставит **новый** адрес, перенос — одна строка реестра, сумма по всем балансам не меняется.

**Заметки к этому блоку:** не обещать больше, чем есть. Подпись доказывает владение **аккаунтом**, а не самим ПК: у ПК свой кошелёк, и его ключа у аккаунта нет.

## Слайд 11 — Рынок и почему сейчас

**Что уже есть у рынка:** спрос на дешёвый инференс, простаивающие потребительские GPU, недоверие к хранению промптов.

**Что даёт протокол:** владелец GPU монетизирует простой; пользователь получает проверяемый чек; structured PII (карты, IBAN, email, IPv4) блокируется до сети. Хранение промптов — только opt-in, зашифровано AES-256-GCM; сервер способен его расшифровать, иначе обучение невозможно. NER (ФИО, адреса) — Фаза 3, отдельным сервисом.

**Почему сейчас:** инференс на потребительском железе стал достаточным для реальных задач — `qwen2.5-coder:1.5b` отвечает на домашнем ПК. Год назад это была демонстрация, сегодня — рабочий узел.

**Честно о рынке:** у нас нет данных о размере спроса на собственном стенде. 759 чеков — это тесты и один живой исполнитель, не рыночный объём. Первый рыночный сигнал даст подключение 10 внешних устройств.

**Заметки:** Не оценивать TAM цифрами из воздуха. Сказать «проверим на первых 10 узлах» — это сильнее.

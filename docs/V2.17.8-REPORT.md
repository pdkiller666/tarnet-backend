# Отчёт `2.17.8-byok-pricing-b` — ставка B′

**Тег:** `v2.17.8-byok-pricing-b` · **Дата:** 2026-11-01
**Задача:** снизить комиссию Tier 6 с `0.0005` до `0.0002` без нарушения
тождества `cashback + burn + treasury === fee` и без падения `delta 0`.

---

## 1. Формула расщепления — что было и что стало

### До правки (`config.js`)

```js
const TIER6 = {
  ORCHESTRATION_FEE_TAR: 0.0005,
  CASHBACK_TAR: 0.0001,
  get cashbackRate() { return this.CASHBACK_TAR / this.ORCHESTRATION_FEE_TAR; },
};
```

`burn` и `treasury` в `config.js` **не существуют** — ни как константы, ни как
геттеры. Директива предполагала три варианта (производные / абсолютные /
геттер от `fee`); фактически верен первый: они выводятся в `server.js`.

### Ключевая находка: `burn`/`treasury` — производные

`server.js`, ветка успеха Tier 6 (`/inference`):

```js
const fee = round(TIER6.ORCHESTRATION_FEE_TAR);
const cashback = round(TIER6.CASHBACK_TAR);
const rest = round(fee - cashback);
const burnTar = round(rest / 2);
const treasuryTar = round(rest - burnTar);   // остаток, не rest/2
```

Значит правка **одной** константы достаточна, и тождество не может разъехаться:
`treasuryTar` — остаток от `rest`, а не второе независимое деление.

### После правки

```js
ORCHESTRATION_FEE_TAR: 0.0002,
CASHBACK_TAR: 0.0001,
```

Проверка:

```
$ node -e "const c=require('./config.js'); ..."
fee 0.0002 cashback 0.0001 rate 0.5
burn 0.00005 treasury 0.00005 sum 0.0002 delta 0
```

`cashbackRate` — **геттер доли**, а не сумма, и равен `0.5`. Директива
опасалась формы `fee * 0.2` — такой связи нет; риск снят.

## 4. `TAR_UTILITY_FEE` vs `ORCHESTRATION_FEE_TAR` — ручной запрос

Поднят изолированный сервер с фейковым провайдером, баланс `1.0 TAR`,
два запроса с одинаковым телом (`tier: 6`), различие — только `paymentMode`.

```json
### tier 6, без paymentMode (HTTP 200)
{ "source": "external_api", "fee_gross_tar": 0.0002, "cashback_tar": 0.0001,
  "burn_tar": 0.00005, "treasury_tar": 0.00005, "delta": 0, "paymentMode": null }

### tier 6 + paymentMode TAR_UTILITY (HTTP 200)
{ "source": "external_api", "fee_gross_tar": 0.0002, "cashback_tar": 0.0001,
  "burn_tar": 0.00005, "treasury_tar": 0.00005, "delta": 0, "paymentMode": null }

fee одинаков (TAR_UTILITY не применяется к Tier 6): true
0.0002 × 0.02 = 0.000004 → round(…, 6) = 0.000004
```

**Вывод: механизмы не пересекаются.** `TAR_UTILITY_*` применяется в
`economics.js` (путь `/work`); ветка Tier 6 в `server.js` не читает
`paymentMode` вообще.

**Гипотеза директивы про округление в 0 — опровергнута.** `0.000004`
представимо при `DECIMALS = 6`; при 2% от `0.0002` получилось бы
`0.000004`, а `burn`/`treasury` стали бы по `0.000002` — тождество
держалось бы. Ограничение не в точности, а в том, что путь не подключён.
Записано в `docs/BYOK-PRICING.md` §5.

Проба удалена после прогона: `tmp-tarutil-probe.js` в репозитории нет.

## 7. Поймал у себя

1. **Директива сказала «11 хардкодов» — их 8.** Остальные три `0.0005` в
   `test-dpouw.js` относятся к цене инструмента `web_search` в каталоге. Если
   править «по счёту», я бы сломал каталог инструментов, а тесты 24.x упали бы
   с невнятным сообщением. Считал не по числу вхождений, а по смыслу.

2. **Гипотеза «2% округлится в 0» была правдоподобной и неверной.**
   `0.0002 × 0.02 = 0.000004`, и `DECIMALS = 6` это хранит. Настоящая причина
   неприменимости — механизм просто не подключён к ветке Tier 6. Разница
   важна: «ограничение точности» звучало бы как технический потолок, а
   реальность — недоделанная связка.

3. **Первый заход на `PITCH-DECK` чуть не испортил сверку казны.** Я начал
   заменять `0.000400` на `0.000100`, и сумма перестала сходиться:
   `0.006762 + 0.0001 − 0.0002 = 0.006662 ≠ 0.006962`. Остановился и
   перечитал: это датированный снимок фактического баланса, а не формула.
   Правильный ход — пометить дату и ставку, а не переписать число.

4. **`grep -c '❌'` по логу дал `1` при нулевых падениях.** Проверял
   строкой `Итого`, а не грубым счётом символов — иначе снова «нашёл бы»
   несуществующее падение.

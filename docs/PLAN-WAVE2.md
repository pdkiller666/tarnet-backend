## 1. Ветка `tier: 6` в `/inference` — выбор модели из реестра

### Что мешает сейчас

`server.js:2876`:

```js
const tier = String(body.tier ?? 'base').toLowerCase();
if (!normalizeTier(tier)) {
  return res.status(400).json({ error: `tier must be one of ${TIERS.join('|')}`, received: tier });
}
```

`normalizeTier` знает только `nano|base|expert` (`config.js:19`). Значит `tier: 6`
падает на 400 ещё до всякой логики. Это правильно: молча принимать шестёрку и
считать её базой — хуже, чем отказать.

### Шаги

1. **Разделить два понятия, которые сейчас слиты.**
   `tier` в теле запроса — это **качество работы** (κ: nano 0.1 / base 1.0 / expert 4.0).
   `tier` в `model_registry` — это **класс модели** (1–6, `CHECK` в схеме).
   Поэтому вводить не `tier: 6`, а отдельное поле:

   ```js
   // ВАРИАНТ А (рекомендуемый): явный выбор модели
   { "modelId": "openrouter/qwen3-coder", "prompt": "..." }

   // ВАРИАНТ Б: ссылка на тир реестра
   { "modelTier": 6, "prompt": "..." }   // при нескольких моделях тира — 409, а не «первая попавшаяся»
   ```

   Причина: `tier: 6` конфликтует с уже занятым полем, и `normalizeTier` придётся
   расширять, ломая экономику (κ для 6 не определён). Отдельное поле ничего не ломает.

2. **Валидация до работы.** Найти строку в реестре, проверить `isAvailable = 1`,
   иначе `409 model_not_available` с `modelId` в теле. Не откатываться молча на base:
   клиент просил конкретную модель, подмена — это обман.

3. **Порядок выбора бэкенда** (в `handleInference`, до ветки `hasActiveWorker()` на `server.js:2943`):

   ```
   modelId задан?
     ├─ нет → текущая логика (worker → external → fallback). Не трогаем.
     └─ да  → provider из реестра:
              local      → воркер (ТОЛЬКО если воркер умеет эту модель)
              openrouter/openai → LLM.callExternal (нужен ключ)
              иначе      → 501 model_provider_not_implemented
   ```

4. **Не расширять `TIERS`.** `tier` в теле остаётся `nano|base|expert` и задаёт κ.
   Класс модели на начисление не влияет — иначе одна и та же работа на разной
   модели платилась бы по-разному, и формула перестала бы быть проверяемой.

**Критерий готовности:** `POST /inference {"modelId":"openai/gpt-4o",...}` либо
честно отвечает `402 reserve_insufficient` (см. §3), либо `501`, либо работает —
но никогда не подменяет модель молча.

## 2. `allowsTraining` — использовать в обработке ответа

### Что мешает сейчас

Поля `allowsTraining` в ответе `/inference` **нет вообще**. Функции `processResponse`
в коде **не существует** (`grep -rn processResponse` → 0 совпадений), поэтому
«использовать в `processResponse`» — это создать её, а не дописать.

### Шаги

1. **Функция-фильтр перед записью ответа** — там, где формируется `result`
   (`server.js:2998-3003`), до `recordWork`. Не отдельный процесс, а одно условие:

   ```js
   /* Ответ модели, запрещающей обучение на своих выходах, не должен попадать
    * в контур Knowledge Loop. Фильтр стоит здесь, а не в дистилляции: позже
    * данных уже не отличить от разрешённых. */
   const tr = modelId ? modelAllowsTraining(modelId) : null; // null = модель не из реестра
   result.trainingAllowed = tr !== false;   // неизвестная модель → false, а не true
   ```

2. **Молчание не равно согласию.** Если `modelId` не в реестре — `trainingAllowed: false`.
   Дефолт в БД `allowsTraining INTEGER DEFAULT 0` уже задаёт эту позицию; код должен
   её повторять, а не спорить с ней.

3. **Отдавать флаг клиенту** в JSON ответа `/inference` рядом с `fallback_reason`:
   `training_allowed: true|false`. Без этого решение не проверить снаружи.

4. **Проверить связку с consent.** Дистилляция требует **двух** условий:
   `allowsTraining = 1` **и** `user_consent.is_opt_in = 1` (`server.js:520-526`).
   Сейчас не выполняется ни одно, потому что потребителя нет.

**Критерий готовности:** `POST /inference` с `openai/gpt-4o` (в реестре
`allowsTraining:0`) → в ответе `training_allowed: false`; с
`deepseek-r1-distill-1.5b` (`allowsTraining:1`) → `true`.

## 3. `reserveUsdc` — проверка перед платными моделями

### Что мешает сейчас

`treasury_state.reserveUsdc` читается только для показа в `/health`
(`server.js:1476`, `1532`). В `/inference` нет ни одного обращения.

### Шаги

1. **Взять requirement из реестра, а не из константы.** У `openai/gpt-4o` в сиде
   `reserveRequiredUsd = 2.5`, у `openrouter/qwen3-coder` — `0`. Проверка читает
   эту колонку, поэтому новый провайдер не требует правки кода.

2. **Проверка перед вызовом `LLM.callExternal`**, в ветке `server.js:2972`:

   ```js
   const req = modelRow.reserveRequiredUsd || 0;
   const have = get('SELECT reserveUsdc FROM treasury_state WHERE id = 1')?.reserveUsdc ?? 0;
   if (req > 0 && have < req) {
     return res.status(402).json({
       error: 'reserve_insufficient',
       requiredUsd: req, availableUsd: have,
       note: 'FIAT reserve is empty [SPEC Phase 2.5]',
     });
   }
   ```

3. **402, а не 500 и не тихий fallback.** Это не сбой сервера: казна пуста —
   легальное состояние. Откат на демо-обработчик здесь был бы подменой платного
   ответа бесплатным без ведома клиента.

4. **Не списывать reserve в этой волне.** `reserveUsdc` остаётся 0 и не двигается:
   списание требует оракула курса (`lastOracleRate: null`), которого нет.
   Волна 2 только **отказывает**, а не считает деньги.

**Критерий готовности:** при `reserveUsdc = 0` запрос к `openai/gpt-4o` →
`402 reserve_insufficient`; к `openrouter/qwen3-coder` (`reserveRequiredUsd: 0`) →
проходит дальше и упирается уже в отсутствие ключа, а не в казну.

## 4. Тесты (5–7 штук)

Формат — как в `test-dpouw.js` (секции с `✅`/`❌`, счётчик в конце).
БД — временная копия, не боевая.

| # | Тест | Ожидание |
|---|---|---|
| 1 | `POST /inference` с `modelId` не из реестра | `400 unknown_model`, ответ содержит присланный `modelId` |
| 2 | `modelId` есть, но `isAvailable = 0` (правим реестр, не сид) | `409 model_not_available` — **не** молчаливый откат на base |
| 3 | `openai/gpt-4o` при `reserveUsdc = 0` | `402 reserve_insufficient`, в теле `requiredUsd: 2.5`, `availableUsd: 0` |
| 4 | `openrouter/qwen3-coder` при `reserveUsdc = 0` (требование 0) | **не** 402 — казна не блокирует бесплатный резерв |
| 5 | `deepseek-r1-distill-1.5b` → флаг обучения | `training_allowed: true` |
| 6 | `openai/gpt-4o` → флаг обучения | `training_allowed: false` (`allowsTraining:0` в сиде) |
| 7 | Запрос без `modelId` (старый клиент) | поведение не изменилось: `tier` валидируется как раньше, `delta: 0` после прогона |

Тест 7 — главный: он доказывает, что Волна 2 не сломала Волну 1.
Тест 2 — второй по важности: он ловит самый опасный класс ошибки, когда отказ
подменяется «первой доступной моделью».

**Инвариант после всей серии:** `conservation.delta === 0`, `holds === true`.
Если новые ветки начали двигать деньги — план реализован неверно.

## 5. Порядок внедрения

1. Тесты 1–2 (валидация и отказ) — не трогают деньги, можно мержить первыми.
2. Тест 7 (регресс) — обязателен до любого кода, меняющего `/inference`.
3. `reserveUsdc` (тесты 3–4) — только отказ, без списаний.
4. `training_allowed` (тесты 5–6) — флаг в ответе, без дистилляции.
5. Роутер `local` → воркер по `modelId` — последним: требует, чтобы воркер
   сообщал, какие модели держит (`/worker/status` сейчас отдаёт одну `model`).

Пункт 5 зависит от того, чего пока нет: воркер объявляет одну модель, а не список.
Пока это так, `modelId` для `provider: local` работать не будет — и обещать его нельзя.

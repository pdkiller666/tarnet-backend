## 2. PII — измерено, решено (вариант B)

**Измерение до решения.** Модели на проде **не было**: `/opt/tarnet/backend-api/.model-cache` отсутствует.
Пакеты стояли (`@xenova/transformers@2.17.2`, `onnxruntime-node`). Замер выполнен реальной загрузкой:

| Параметр | Значение |
| :--- | :--- |
| Кэш модели | **105 MB** (`du -sh /tmp/pii-cache`) |
| Пиковый RSS | **687 MB** (`VmHWM`), текущий 670 MB |
| Загрузка | **4.6 с** |
| RAM прода | 1642 MB всего, **1165 MB доступно**, swap 0 |
| Порог `minFreeMb` | 900 — загрузку **пропустил бы** |

RAM не блокер. Блокер — **точность**. Замер на той же модели:

| Промпт | NER нашёл | При пороге 0.95 |
| :--- | :--- | :--- |
| `Explain how TCP handshake works` | `B-ORG: T (0.94)`, `I-ORG: ##CP (0.64)` | **блок** |
| `Compare React and Vue for a dashboard` | `MISC: Co/##are/Re/##act/and/V/##ue` | **блок** |
| `Berlin → Munich by train` | `LOC: Berlin (1.00)`, `LOC: Munich (1.00)` | **блок** |
| `Иван Иванович Петров` | `PER: И (0.96)`, `И (0.99)` | блок (верно) |
| `function sum(a,b){...}` | ничего | пропуск (верно) |

**Главный факт, меняющий постановку задачи:** гейт Tier 6 (`server.js:6169`) вызывает `LLM.piiCheck`, а тот
читает **только** `STRUCTURED_PATTERNS` (`llm-adapter.js:40-56`). `piiClassifier.classify` с NER вызывается
в двух других местах — `/distill/record` (`4455`) и внешняя ветка (`6955`). Значит «включить ONNX» **не
изменило бы гейт Tier 6** — он regex-only по устройству, а риск ложных блокировок добавился бы в облачную ветку.

**Решение: вариант B** — структурный regex остаётся окончательным гейтом, NER → Фаза 3 за отдельным сервисом.
Записано в `docs/PII-DECISION.md`. `docs/PITCH-DECK.md:239` уже честно сообщает, что NER не поднят — правки
не потребовалось.

**Проверено живьём, до и после:** `POST /inference` c `modelId: deepseek/deepseek-chat`:
- карта `4532015112830366` → `422 {error:"PII_BLOCKED", matches:["card"], required_confidence:0.95}`
- **ФИО «Иван Иванович Петров» → `401 AUTH_MISSING_KEY`** — при наличии ключа имя ушло бы провайдеру открытым текстом.

Это ограничение записано в манифесте и в `PII-DECISION.md`, а не спрятано.

## 3. Контракт onion — документация была права, ошибка в диагностике

Первичная гипотеза («документация врёт, клиент по доке получит 400») **не подтвердилась**.

| Источник | Поле |
| :--- | :--- |
| `server.js:5090` (обработчик) | `{routeNodes, prompt, clientAddress, model}` |
| `DEMO-RUNBOOK.md` шаг 4 | `{"routeNodes":[...],"prompt":"demo"}` — **совпадает** |
| `app/app.js:1154` (PWA) | `prompt` — **совпадает** |
| `test-dpouw.js` 8.15 | `prompt` — **совпадает** |

То есть контракт менять не нужно: врал мой тестовый запрос с `messages[]`, а не документ. Настоящий дефект был
узкий: на `messages[]` сервер отвечал общим `prompt must be a non-empty string`, по которому нельзя понять, что
дело в имени поля.

**Исправлено (только диагностика, не контракт):**
```json
400 {"error":"expected_field_prompt",
     "note":"Этот маршрут принимает `prompt` (строка), а не `messages[]` (OpenAI-формат)...",
     "received":"messages","expected":"prompt",
     "example":{"routeNodes":["0x..."],"prompt":"demo"}}
```
Закреплено тестами 8.15: `messages[]` → 400 с явным полем; `prompt` → 200 (контракт не менялся).

Живая проверка прода: `prompt` + 3 `routeNodes` → `200 {"delivered":true,"hops":3}`.

## 5. Поймал у себя

1. **«985/25/12 = 1022» — неверно.** Я посчитал `test-mesh-worker.js` третьим набором тестов. На деле это
   процесс-фикстура, которую `test-mesh.js` спавнит (`test-mesh.js:99`); запуск вручную даёт `RC=0` **без
   единой проверки** («нужны `WORKER_PRIV_B64`…»). А «12» — это `conservationTier6.calls`, вызовы Tier 6, а не
   тесты. Настоящее число тогда было **1010**. Исправлено во всех документах.
2. **`model` вместо `modelId`.** Первые живые проверки гейта Tier 6 уходили в `deterministic_fallback`, потому
   что поле называется `modelId` (`server.js:6104`). Чуть не записал «гейт недостижим» — это была бы ложная
   находка о чужом коде.
3. **«Документация врёт про onion» — не подтвердилось.** Проверка `DEMO-RUNBOOK` и PWA показала, что документ
   прав, а неверен был мой запрос. Правку кода под несуществующее расхождение не делал.
4. **`berd-base-NER`** — опечатка в §Б.8, исправлена до коммита.

## 6. Хрупкое и что осталось

- **Имена в свободном тексте не блокируются.** Tier 6 нельзя подавать как безопасный для произвольных
  пользовательских промптов — только для задач без персональных данных. NER — Фаза 3, отдельным сервисом.
- **RAM-запас на VPS:** 1642 MB всего, 1165 доступно. Загрузка NER оставила бы ≈478 MB свободными при живом
  сервисе. Второй такой модуль туда не влезет.
- **`required_confidence: 0.95` в теле `422`** — унаследованное поле, сравнения с ним никто не делает. Убирать
  отдельной правкой, чтобы не менять контракт ошибки в этом же коммите.
- **`active_workers: 0`** — живого LLM по-прежнему нет, ответы собирает детерминированный обработчик.
- **Тег не ставился** — задачи 1–3 закрыты, но по директиве следующий тег после них, отдельным шагом.

# DEMO-SCRIPT — демонстрация TarNet инвестору

> **Проверено на стенде 28.10.2026, 21:15 MSK.** Версия `2.12.9-migrate-claim`, 812 тестов.
> Каждый шаг ниже прогнан вживую. Где результат зависит от подготовки машины —
> это сказано прямо, а не спрятано.
>
> **Прод на момент написания:** `llm_mode: deterministic_fallback`, `active_workers: 0`.
> Зелёный баннер на шаге 1 появляется только после того, как вы запустите воркер
> на своей машине. Это не декорация — без воркера баннер честно жёлтый.

---

## Что нужно до начала (5 минут)

| Что | Зачем | Проверка |
|---|---|---|
| Node 18+ | Воркер и установщик | `node -v` |
| Адрес кошелька из PWA | Воркер должен считать на **ваш** кошелёк | виден под балансом |
| Ключ OpenRouter (для шага 2) | Tier 6 BYOK — вызов идёт с вашего аккаунта | `sk-or-v1-…` |
| Ollama с моделью (для шага 3) | Настоящий локальный инференс | `ollama list` |
| 0.01 TAR на балансе | Оплата вызовов | `/faucet` в PWA |

Без Ollama шаг 3 покажет шаблон вместо ответа модели — см. оговорку в шаге 3.
Это ограничение вашей машины, а не протокола, и сценарий его не скрывает.

## Шаг 0 — Проверить, что стенд жив (15 секунд)

```bash
curl -s https://v1107336.hosted-by-vdsina.com/health | head -c 200
```

Ожидаемо: `HTTP 200`, в теле `"status":"ok"`, `"buildVersion":"2.12.9-migrate-claim"`.

Если не 200 — дальше идти нельзя, остальное не имеет смысла.

## Шаг 1 — Зелёный баннер: ваш ПК в сети

**Зачем инвестору:** сеть — это не схема на слайде, а процесс на его машине.

1. Открыть PWA: `https://v1107336.hosted-by-vdsina.com/app/`
2. Скопировать свой адрес из-под баланса (40 hex после `0x`).
3. Поставить воркер на свою машину — установщик подставит адрес сам:

   **Windows:**
   ```
   https://v1107336.hosted-by-vdsina.com/install/install.bat?addr=ВАШ_АДРЕС
   ```

   **macOS:**
   ```
   https://v1107336.hosted-by-vdsina.com/install/install.command?addr=ВАШ_АДРЕС
   ```

   Оба эндпоинта проверены: `HTTP 200` с адресом, `400 addr required` без него.

4. Запустить воркер. В консоли должно появиться:

   ```
   TarNet worker
   сервер:  https://v1107336.hosted-by-vdsina.com
   адрес:   0x…   ← должен совпасть с адресом в PWA
   бэкенд:  ollama (или fallback)
   ```

5. Обновить PWA. Баннер наверху — **зелёный**: «✅ Сеть активна. Ваш ПК обрабатывает задачи.»

**Что говорить:** «Этот ПК сейчас в сети TarNet и готов считать.»

**Чего не говорить:** «сеть работает постоянно». Она работает, пока запущен
процесс. Закроете терминал — через несколько секунд баннер станет жёлтым.

> **Почему зелёный баннер не появляется сам.** Он требует совпадения двух
> условий: воркер зарегистрирован **и** его адрес совпадает с адресом в PWA.
> Если адреса разные, баннер будет `online-other` — «сеть жива, но это не ваш
> ПК». Это защита от вранья в обе стороны, а не баг.

## Шаг 2 — Tier 6 (BYOK): кэшбэк с вашего ключа

**Зачем инвестору:** протокол умеет работать с внешним провайдером и
возвращать часть комиссии пользователю.

1. В PWA открыть настройки ключа, вставить ключ OpenRouter (`sk-or-v1-…`).
   Ключ остаётся в `localStorage` вашего браузера и уходит только заголовком
   `X-Provider-Key` на один запрос.
2. В списке моделей выбрать облачную: **`openrouter/qwen3-coder`** (tier 6).
3. Отправить запрос, например «Say hi in one word».
4. В ответе под текстом — блок квитанции с кэшбэком.

**Проверенный ответ сервера (стенд, 21:15 MSK):**

```json
{
  "source": "external_api",
  "provider": "openrouter",
  "model": "qwen/qwen3-coder",
  "cashback_tar": 0.0001,
  "funded_by": "client",
  "paid_by": "device",
  "economics": {
    "fee_gross_tar": 0.0005,
    "cashback_tar": 0.0001,
    "burn_tar": 0.0002,
    "treasury_tar": 0.0002,
    "delta": 0
  }
}
```

**Что сказать:** «Комиссия 0.0005 TAR разошлась без остатка: 0.0001 вернулось
пользователю кэшбэком, по 0.0002 сожжено и ушло в казну. `delta: 0` — это
проверяемое тождество, а не обещание.»

**Чего не говорить:** «Tier 6 работает под нагрузкой». Проверена **одна**
сделка с живым ключом (`tier6_calls: 1`). Лимиты провайдера и параллельные
резервы на потоке не проверялись.

## Шаг 3 — Локальная модель: считает ваш ПК

**Зачем инвестору:** работа уходит на машину пользователя, а не на наш сервер.

1. Убедиться, что Ollama запущена и модель есть:
   ```bash
   ollama list        # должна быть qwen2.5-coder:1.5b или qwen2.5-coder-7b
   ```
2. В PWA выбрать **локальную** модель: `qwen2.5-coder:1.5b` или `qwen2.5-coder-7b`.
3. Отправить запрос на код: «Напиши функцию сложения двух чисел на Python».
4. В квитанции — `provider: home_worker` и адрес **вашего** ПК в поле воркера.

**Что сказать:** «Ответ посчитала не наша инфраструктура, а этот ноутбук.
Сервер только передал задачу и учёл работу.»

### Оговорка, которую нужно произнести вслух

**Если Ollama не установлена**, воркер не падает — он честно отвечает шаблоном
и помечает это флагом `emulated: true`:

```
"source": "live_llm",
"provider": "home_worker",
"emulated": true,
"response": "Воркер получил запрос: «…». Модель на этом ПК не настроена,
             поэтому текст собран по шаблону."
```

Проверено на стенде: воркер без Ollama и без облачных ключей отдаёт именно это.

**Как вести себя:** если Ollama нет — сказать прямо «модель на этой машине не
поставлена, воркер вернул шаблон и сам это пометил». Показывать шаблон как ответ
модели нельзя: это ровно тот обман, который инвестор проверит первым делом.

## Шаг 4 — Инвариант и объём: `/health` и `/summary`

**Зачем инвестору:** цифры можно пересчитать самому.

```bash
curl -s https://v1107336.hosted-by-vdsina.com/health   | python3 -m json.tool | grep -A6 conservation
curl -s https://v1107336.hosted-by-vdsina.com/summary  | python3 -m json.tool | head -20
```

**Проверенный снимок прода (28.10.2026, 21:15 MSK):**

```json
"conservation": {
  "gross": 72.500819,
  "distributed": 72.500819,
  "delta": 0,
  "holds": true,
  "reservedTar": 0,
  "inconsistentRows": 0
}
```

```json
"receipts": 721,
"totalRewardTar": 72.117293,
"workers": 83
```

**Показать арифметику на экране** — это самое сильное место демо:

```
72.117293 (выплаты) + 0.185113 (сожжено) + 0.185113 (казна) + 0.013300 (роялти)
= 72.500819 (оборот)
```

**Что сказать:** «Ни один TAR не появился и не исчез. Это тождество, которое
вы можете пересчитать из двух публичных эндпоинтов.»

**Чего не говорить:** «721 чек — это рынок». Это тесты и один живой
исполнитель. Рыночного объёма у нас пока нет, и говорить иначе — врать.

## Шаг 5 — Выключить воркер: честный fallback

**Зачем инвестору:** система не ломается, когда узел уходит.

1. Остановить воркер: `Ctrl+C` в его терминале.
2. Подождать несколько секунд (окно присутствия), затем обновить PWA.
3. Баннер станет жёлтым: «⚠️ Ваш ПК не в сети. Ответы генерируются
   демо-обработчиком.»
4. Отправить запрос — ответ придёт, но помеченный как детерминированный:
   `"source": "deterministic_fallback"`.

**Проверено:** после гашения процесса `/worker/status` отдаёт
`{"active_workers":0,"mode":"deterministic_fallback"}`.

**Что сказать:** «Сеть не падает вместе с узлом — она переходит в честно
помеченный режим. Пользователь видит, что ответ не от модели.»

**Чего не говорить:** «fallback отвечает так же хорошо». Он отвечает шаблоном,
и это видно в поле `source`.

## Шаг 6 (бонус) — Перенос баланса со старого кошелька

**Зачем инвестору:** показывает, что мы закрываем свои же старые ошибки.

1. В PWA открыть вкладку **«Мои устройства»** → карточка
   «Перенести баланс со старого кошелька».
2. Вставить старый адрес (без ключа), нажать **«Проверить»** — карточка
   покажет сумму к переносу.
3. Нажать **«Перенести»** — браузер подпишет запрос ключом Ed25519.
4. Баланс появится на текущем кошельке; старый обнулится.

**Проверенный результат (стенд, реальная подпись):**

```
старый (без ключа): 20 TAR  →  0
новый  (с ключом):   0      → 20
строк kind='migrate' в реестре: 1
```

Повторный клейм того же адреса — `409`, статус показывает
`"claimed":true, "blockedReason":"ALREADY_MIGRATED"`.

**Что сказать:** «Раньше адрес в приложении создавался без ключа, и начисления
на нём были заморожены навсегда. Теперь их можно забрать — но только подписью,
поэтому чужой баланс увести нельзя.»

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Баннер жёлтый при живом воркере | Адрес воркера ≠ адрес в PWA | Перезапустить установщик со своим `?addr=` |
| `400 addr required` у установщика | Не передан адрес | Добавить `?addr=0x…` (40 hex) |
| `429 too_many_requests` | Лимит записи: 10 запросов за 60 с с IP | Подождать минуту |
| Tier 6 → `401` без вызова провайдера | Нет ключа или он кривой | Проверить `X-Provider-Key` |
| Tier 6 → `402` | Мало TAR на балансе | `/faucet` в PWA |
| Шаг 3 отдаёт шаблон | Нет Ollama | Поставить Ollama **или** сказать честно |
| Баннер «Сервер недоступен» | Стенд лежит | Шаг 0, дальше не идти |

## Три фразы, которые нельзя говорить

1. **«Сеть работает постоянно»** — работает, пока запущен процесс.
2. **«Tier 6 работает под нагрузкой»** — проверена одна сделка.
3. **«721 чек — это рыночный объём»** — это тесты и один исполнитель.

Всё остальное на этом сценарии — правда, и её можно проверить на месте.

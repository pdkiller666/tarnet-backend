## 1. Четыре правки документов — «Было / Стало»

### 1.1. `README.md` — авто-включение по RAM

| | Текст |
| :--- | :--- |
| **Было** | «На продакшене с 4+ ГБ RAM — включён по умолчанию» |
| **Стало** | «Авто-включения по объёму RAM нет… единственное условие — `process.env.TARNET_PII_ONNX === '1'` (`pii-classifier.js:48`); `minFreeMb: 900` — предохранитель против загрузки, а не триггер» |

**Почему это была самая опасная ложь.** Читатель решал бы так: на его VPS с 2 ГБ
модель не поднимется, а на 4+ поднимется сама. Второе неверно — на сервере с любой
памятью модель останется выключенной, пока флаг не выставлен руками.

**Доказательство:**

```
$ sed -n '48p' pii-classifier.js
const ONNX_ENABLED = process.env.TARNET_PII_ONNX === '1';
```

Единственное условие. Ветка `minFreeMb` — предохранитель, а не триггер загрузки:

```
$ sed -n '181,182p' pii-classifier.js
        if (freeMb !== null && freeMb < this.minFreeMb) {
          this._loadError = `refused to load ${this.modelId}: only ${freeMb} MB RAM available, need ${this.minFreeMb} MB`;
```

Проверка только **отказывает** в загрузке, когда памяти мало. Поднять модель она не может:
без `TARNET_PII_ONNX=1` до этой строки управление не доходит вовсе.

### 3.3. Инвариант: два числа стояли рядом без объяснения

Было: `80.387229 + 0.186138 + 0.186138 + 0.013300 = 80.772805`.
Стало:

```
82.016486 + 7.152436 + 0.188638 + 0.188638 + 0.013300 = 89.559498
```

Отдельно объяснено, почему `totalRewardTar` (`89.168922`) **меньше** `gross`
(`89.559498`) на `0.390576`: это разные совокупности, а не расхождение леджера.
`totalRewardTar` = блочная награда (`82.016486`) + комиссия исполнителям (`7.152436`);
сжигание (`0.188638`), казна (`0.188638`) и lora-роялти (`0.0133`) в него не входят.

**Почему это важно.** Инвестор, сложивший два стоящих рядом числа и получивший
`0.39` невязки, решил бы, что леджер не сходится. Раньше объяснения не было.

## Шаг 1. Открыть `/app/` на телефоне

```
https://v1107336.hosted-by-vdsina.com/app/
```

Телефон подключается к тому же узлу, что и ПК: это PWA, ставится на домашний
экран через «Поделиться → На экран Домой». Открывается без установки из стора.

**Смысл:** вход один — TarNet ID, кошелёк создаётся на устройстве, приватный
ключ не уходит на сервер. Это не «ещё одно приложение», это тот же аккаунт.

**Если не открылось:** проверить `curl -o /dev/null -w "%{http_code}" <URL>/app/`
— должно быть `200`. Туннель мог умереть; тогда поднимать заново
`scripts/tarnet-tunnel.sh` на VPS.

## Шаг 2. Нажать **Nano-Node**

Кнопка `Nano-Node` на главном экране (`id="nanoBtn"`). Узел регистрируется, в
`/nodes` появляется новая запись с `tier`.

**Смысл:** порог входа — обычный телефон. Тир `nano` даёт κ = 0.1 (коэффициент
работы), но участвовать можно с нуля. Это ответ на «зачем мне ваш токен, если
у меня нет фермы».

**Что сказать про тиры прямо:** `nano` — телефон, `base` — ноутбук,
`expert` — машина с GPU, `heavy` — сервер. В **комитет валидаторов** входят
только `expert` и `heavy`: узел на телефоне не может проверять чужие LoRA.
Сейчас в комитете 22 узла из 133.

## Шаг 3. Открыть `/health` в браузере — показать `delta: 0`

```
https://v1107336.hosted-by-vdsina.com/health
```

Смотреть три поля:

```json
"conservation": { "delta": 0, "holds": true },
"buildVersion": "2.4.1-tier-fix",
"llm_mode": "deterministic_fallback"
```

**Смысл:** `delta: 0` — баланс сети сходится. Сколько токенов выпущено, столько
и распределено: `gross = distributed`, расхождение ноль. Это главная защита от
«а вы просто рисуете цифры в базе» — инвариант проверяется на каждом запросе.

**Честная оговорка:** `llm_mode: deterministic_fallback` означает, что модель
сейчас отвечает шаблоном. Это состояние **до** шага 5. Не прятать: сказать, что
настоящий инференс включается живым воркером, и показать это следующим.

## Шаг 4. Открыть `/p2p/status` — показать 3 узла

```
https://v1107336.hosted-by-vdsina.com/p2p/status
```

```json
"transport": "websocket",
"routeNodes": [ "0x2491ab72…", "0xabe139a7…", "0x3281abaf…" ]
```

**Смысл:** это не «сервер и клиент», а три relay-узла, через которые идёт
луковичный маршрут. Каждый слой шифруется RSA-ключом своего узла — relay видит
только следующий адрес, но не промпт.

**Проверка, которую стоит показать живьём** (она убедительнее экрана):

```bash
curl -s -X POST https://v1107336.hosted-by-vdsina.com/inference/onion \
  -H 'Content-Type: application/json' \
  -d '{"routeNodes":["0x2491ab72f3cdfa132059df7e5cf08a0ea4c9fe25","0xabe139a759a3e77649eabc45fa5319e7085b2610","0x3281abaf01c3d746d09934b8e3a64344c0de3640"],"prompt":"demo"}'
```

Ответ: `"delivered": true`, `"hops": 3`, `"packetBytes"` ≈ 2.4 КБ
(число зависит от длины промпта — не называть точное значение вслух,
если оно изменится). Доставка реальная, не заглушка.

## Шаг 5. Запустить `worker.js` на ПК — показать `llm_mode: worker`

```bash
curl -O https://v1107336.hosted-by-vdsina.com/download/worker.js
TARNET_API_URL=https://v1107336.hosted-by-vdsina.com node worker.js
```

Зависимостей нет, нужен Node 18+. Затем обновить `/health`:

```json
"llm_mode": "worker",
"active_workers": 1
```

**Смысл:** тот самый ПК стал вычислительным узлом сети. Промпт ушёл на него,
там посчитан настоящей моделью (Ollama / Groq / OpenRouter), вернулся с чеком.
Сервер не считал — сервер только свёл баланс.

**Окно жизни:** воркер считается живым **120 секунд** после последнего опроса
(`WORKER_ACTIVE_WINDOW_MS`). Закрыли терминал — через 2 минуты `llm_mode`
вернётся в `deterministic_fallback`. Это норма, не поломка.

**Дублирующий экран:** `GET /worker/status` отдаёт то же в поле `mode`, плюс
`pending_tasks` и список воркеров — удобно, если `/health` уже открыт.

## Если что-то упало во время демо

| Симптом | Что делать |
|---|---|
| `/app/` не открывается | туннель умер → `scripts/tarnet-tunnel.sh` на VPS |
| `delta` ≠ 0 | **остановить демо**, это дефект экономики, не «глюк» |
| `/p2p/status` без узлов | `systemctl restart tarnet`, проверить порты 4001/4002 |
| `llm_mode` не стал `worker` | воркер не опрашивает: проверить `TARNET_API_URL` и что процесс жив |
| `/inference/onion` даёт `delivered: false` | смотреть `deliveryError`; пакет валиден, сеть — нет |

## Что нельзя обещать инвестору

Эти вещи в коде есть как **спецификация**, не как работа:

- **Benchmark Gate** (`verifyAdapter`) — возвращает `implemented: false`. Комитет
  валидаторов **выбирается**, но проверки адаптеров нет: ни бенчмарка, ни
  подписей валидаторов.
- **ECVRF** — жребий комитета сейчас детерминированный sha256-поток. Он
  пересчитывается любым участником, но предсказуем заранее. Настоящий VRF —
  Фаза 3.
- **Onion Routing** — работает для демо-сети из 3 узлов. Продовый маршрут по
  произвольным узлам из БД не доставляется: у записей нет транспортного адреса.
- **ONNX-классификатор PII** — выключен на этом VPS: модель держит 532 МБ RSS
  из 1642 МБ. Сейчас работает только regex-ветка (телефон, email, карта, IBAN).
  Имена ловит модель — она включится на сервере с 4+ ГБ RAM.

Формулировка для инвестора: «ядро экономики работает и сходится; валидация
адаптеров и VRF — следующие два спринта, спека готова, кода нет».
